# The Modern Project Management Triangle

The classic Project Management Triangle represents the three primary constraints that every project manager must balance:

```
                  SCOPE
             (What to Build)
                    ▲
                   / \
                  /   \
                 /     \
                /       \
               /         \
              /           \
             /             \
            /               \
 RESOURCES ---------------- SCHEDULE
    (Who)                    (When)
```

Every project decision involves balancing these three dimensions.

Changing one side almost always affects one or both of the others.

Examples:

* Increase scope → Need more people or more time.
* Reduce schedule → Need more people or less scope.
* Reduce resources → Need more time or reduced scope.

The role of a project manager is to continuously balance these competing constraints.

---

# Why Quality Is NOT a Fourth Constraint

Many project management diagrams incorrectly show **Quality** as a fourth corner or as a separate dimension.

A better way to think about quality is:

> **Quality is part of Scope.**

Every requirement should include measurable **Acceptance Criteria** that define what "done" means.

For example:

**Requirement**

* User can upload a PDF file.

**Acceptance Criteria**

* Files up to 20 MB are accepted.
* Upload completes within 3 seconds.
* Invalid files display a friendly error message.
* Virus scanning is completed successfully.
* Upload works on Chrome, Edge, Firefox, and Safari.

If these criteria are not met, the feature is incomplete.

Quality is therefore embedded inside the scope definition rather than being a separate dimension that can be negotiated.

A project manager should never "reduce quality" to meet a deadline.

Instead, the project should reduce **scope** while maintaining the agreed acceptance criteria.

# Waterfall Project Management

Traditional Waterfall projects allow all three dimensions to be adjusted.

```
                  SCOPE
                (Variable)

                    ▲
                   / \
                  /   \
                 /     \
                /       \
               /         \
              /           \
             /             \
            /               \

 RESOURCES ---------------- SCHEDULE
 (Variable)                (Variable)
```

Typical project discussions include:

* Can we hire more developers?
* Can we extend the deadline?
* Can we reduce functionality?
* Can we increase the budget?
* Can we delay the release?

Waterfall projects continuously rebalance all three dimensions throughout execution.

---

# Agile Project Management

Agile takes a very different approach.

The team size and iteration duration are normally fixed.

Only the amount of work changes.

```
                  SCOPE
                (Variable)

                    ▲
                   / \
                  /   \
                 /     \
                /       \
               /         \
              /           \
             /             \
            /               \

 RESOURCES ---------------- SCHEDULE
    Fixed                    Fixed
```

Instead of changing deadlines or adding people, Agile teams adjust the backlog.

The highest-priority work is completed first, while lower-priority work moves to future iterations.

This allows teams to maintain predictable delivery cadence without sacrificing quality.

# Waterfall vs Agile

| Dimension     | Waterfall                            | Agile                                |
| ------------- | ------------------------------------ | ------------------------------------ |
| Scope         | Variable                             | Variable                             |
| Resources     | Variable                             | Usually Fixed                        |
| Schedule      | Variable                             | Usually Fixed                        |
| Quality       | Defined by Scope acceptance criteria | Defined by Scope acceptance criteria |
| Primary Lever | Any dimension may change             | Scope changes first                  |
| Planning      | Upfront                              | Continuous                           |
| Delivery      | Big Bang                             | Incremental                          |

---

# The Golden Rule

A useful principle for modern software project management is:

> **Never compromise quality to meet schedule.**

Instead:

* Keep the team stable.
* Keep the schedule predictable.
* Adjust scope based on business priority.

This philosophy is one of the key reasons Agile methodologies have become the dominant approach for software development organizations worldwide.
